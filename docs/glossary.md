# AI用語集

`history/` 配下のサイト（デイリーニュース・最新トレンド・年表）と、その元データである `report/` 25本・`everyday_news/` に**実際に登場する用語**だけを収録した用語集。一般的なAI辞書ではなく「このサイトを読んでいて詰まる語」に絞っている。

- 対象データ: `report/*.md`、`history/daily-data.js`、`history/news.html`、`history/generative.html`、`everyday_news/2026*.md`

## 1. エージェント・自律化

| 用語 | 正式名称 / 読み | 意味 |
|---|---|---|
| **エージェンティックAI** | Agentic AI | AIが「質問に答えるツール」ではなく「目的を与えられて自律的に実行する主体」として動く形態。2026年の最大の構造転換とされ、企業ソフトへの組み込み率は2024年の1%未満から2028年に33%へ拡大すると予測されている。 |
| **マルチエージェント / MAS** | Multi-Agent System | 役割の異なる複数のAIエージェントが相互に通信・交渉して1つのタスクを遂行する構成。サプライチェーンの自律交渉やサイバー防御（赤・青・緑の3エージェント連携）などで実運用が始まっている。 |
| **A2Aプロトコル** | Agent-to-Agent Protocol | エージェント同士が自律的に交渉・協調するための通信標準。各エージェントが自分の能力を「AgentSkill」として公開し合う。150以上の組織が支持し2026年にv1.0安定版へ到達。 |
| **MCP** | Model Context Protocol | LLMを外部ツールやデータソースに接続するための標準インターフェース。エージェントが外部環境を操作する際の事実上の共通規格になりつつあり、対応ツールを差し替えるだけで能力を拡張できる。一方で、接続先が増えるほど権限とサプライチェーンの管理が新たな攻撃面になる。 |
| **ハーネス** | Harness | モデルの重みそのものではなく、その周囲にあるプロンプト・記憶構造・ツールインターフェースの総称。近年のエージェント性能向上の主戦場はモデル更新からハーネスの設計・書き換えへ移っている。 |
| **RHI** | Recursive Harness self-Improvement（再帰的ハーネス自己改善） | 過去の改変履歴をペアワイズ・フィードバックで反復最適化し、ハーネスを自動で書き換え続ける手法。推論コストを最大60%削減しつつ、低推論努力のモデルが最大推論努力モデルの性能上限を超えられることを実証した。GPU再学習が不要なため極めて低コストで、バージョン管理による即時ロールバックも可能。 |
| **RSI** | Recursive Self-Improvement（再帰型自己改善） | システムが環境との相互作用を通じて自分自身の構成要素を改変し続けること。単一出力を推敲する従来の自己修復（Self-Refinement）と異なり、基盤モデルの重み更新から推論時のハーネス書き換えまでを射程に入れる。 |
| **DGM** | Darwin Gödel Machine | Jenny Zhangらが開発した自己改変アーキテクチャ。凍結したベースモデルの周囲に「自分のPythonソースコードを読み書き・実行・管理するツール群」を統合し、サンドボックス内で進化的探索（MAP-Elites / Novelty Search）を回す。80回の自己変異を経て、コード編集ツール・文脈管理スキーム・査読メカニズムを自律的に発見した。 |
| **CUA** | Computer-Using Agent | 画面を見てGUIを操作するエージェント。固定座標やセレクタに依存する従来のRPAと違い、UI変更への追随・例外時のリトライ・複数アプリ横断の判断ができる。APIが整備されていないメインフレームや外部ポータルの自動化に使われる。 |
| **ManAIgement** | （Management + AI の造語） | 物理現場のリアルタイム稼働データと経営判断を直結させた自律的経営形態。世界モデルで3Dデジタルツインに同期した現場情報をエージェント群が再配分し、上位の戦略推論モデルが資本配分・設備投資を評価する。導入には「合成意思決定トレース」による監査可能性の確保が前提となる。 |
| **AIソフトウェアエンジニア** | AI Software Engineer | コード補完にとどまらず、要件の理解・実装・テスト・修正までを一貫して担うエージェント型の開発者。人間の役割は「書く人」から、仕様を与えて成果物を検証する「レビューする人」へ移り、シート課金から成果連動課金への移行を促す典型例とされる。 |
| **OpenClaw** | （旧 Clawdbot / Moltbot） | 既存のLLM（Claude、GPT、DeepSeek等）をローカル環境の自律エージェントとして動かすオープンソースプロジェクト。2026年に爆発的に普及し、2.0でセットアップ簡素化と共同セッションに対応した。 |
| **A-Corp** | Agent Corporation（エージェント法人） | AIエージェントに法人格に相当する枠組みを与え、保有する計算資源契約や預金を法的に可視化する構想。違反時に「マスターキーの剥奪」や計算リソース差し押さえという実効性のある法執行レバーを持たせることを狙う。 |
| **IETF AIMS** | draft-klrc-aiagent-auth | AIエージェントの認証・認可の標準化フレームワーク。エージェントを「サーバーレスコンテナやマイクロサービスと同等のシステムワークロード」として扱い、WIMSE識別子（SPIFFE ID）を動的発行する。ISO/IEC 42001の AIMS（AI Management System）とは全くの別物なので注意（→ 6章）。 |
| **DI（意思決定知能）** | Decision Intelligence | 因果推論とマルチエージェント協調を統合し、BIの受動的な可視化から自律的な実行判断まで踏み込む概念。Palantir「Foundry/AIP」導入企業では港湾封鎖や関税変更時に数千通りの代替調達ルートを即時試算し、意思決定サイクルを数週間から数分へ短縮した。市場規模は2025/2026年の170億〜200億ドルから2030年代初頭に400億〜580億ドルへ、CAGR15〜30%で拡大すると見込まれる。 |
| **Claude Tag** | Anthropic | Anthropicが2026年7月にSlack上に投入した常駐型AIエージェント。当初はメッセージを1件ずつ評価する方式だったが、8月24日の更新で会話全体の文脈を読み取り、求められなくても自ら会話に割り込んで応答するようになった。メンションから直接Artifactを作成できる機能もあり、チャットツールに常駐させる形のエージェント活用例として扱われる。 |

## 2. モデル技術・学習手法

| 用語 | 正式名称 / 読み | 意味 |
|---|---|---|
| **LLM** | Large Language Model（大規模言語モデル） | 大量のテキストで学習した言語モデル。本サイトで単に「モデル」と言う場合はほぼこれを指す。近年はMoEによる疎な活性化、推論時スケーリング、コンテキストウィンドウの拡大という3方向で性能と効率が伸びている。 |
| **MoE** | Mixture of Experts（混合エキスパート） | 全パラメータを毎回計算せず、入力トークンごとに最適なサブネットワーク（Expert）だけを起動する構造。総パラメータ284Bでもアクティブ13Bで動く、といった表記はこの仕組みによる。推論効率を劇的に改善し、コモディティ推論の価格低下を牽引している。 |
| **推論時スケーリング** | Test-time / Inference-time Scaling | 学習時ではなく推論時に計算量（思考時間）を積み増して性能を上げる手法。「推論モデル」「Thinking」系モデルの基本原理。ロボティクスへの応用では遅延（Latency）が最大の課題になる。 |
| **RLVR** | Reinforcement Learning with Verifiable Rewards | 機械的に正誤を確定できるルールベースのバイナリ報酬を使う強化学習。人間による教師データ（SFT）なしでも、モデルが自発的に「自己検証」「自己省察」「試行錯誤の反復」を獲得できることをDeepSeek-R1が示した。 |
| **GRPO** | Group Relative Policy Optimization | 価値関数モデルを不要にし、グループ内の相対的な報酬評価だけで学習する手法。計算コストを大幅に抑えながら推論プロセスの自律的改善を実現する。派生としてSAGE（Skill Augmented GRPO）がある。 |
| **SFT / ポストトレーニング** | Supervised Fine-Tuning | 事前学習済みモデルに対して後段で行う調整工程の総称。アーキテクチャを変えずポストトレーニングのみを再実施してフラッグシップ超えを主張する例（DeepSeek V4-Flash-0731）もある。 |
| **蒸留** | Distillation | 高性能モデルの出力を教師データにして、小さく安価なモデルに能力を移す手法。中国6社が米フロンティアモデルに組織的な蒸留を仕掛けたとして米当局が共同勧告を出すなど、地政学的な争点にもなっている。 |
| **オープンウェイト** | Open-weight | モデルの重みファイルを公開する形態。ソースコードやデータまで含む「オープンソース」とは区別される。Apache 2.0等で公開された中国系モデルが推論価格を押し下げている。 |
| **コンテキストウィンドウ** | Context Window | モデルが一度に参照できるトークン数の上限。Gemini 3.5 Proの200万トークンのように拡大競争が続く一方、長い文脈に状態を持たせる設計は破綻しやすく、実務ではエージェントの状態をコンテキストではなく外部テーブルに書き出す構成が採られる。 |
| **量子化** | Quantization | パラメータの数値精度を落として推論を軽量・高速化する技術。重みを32ビット浮動小数点から8ビットや4ビットへ圧縮し、精度を保ちつつメモリ消費を50〜75%削減する。プルーニングや蒸留と並ぶ推論コスト最適化の定番手段。 |
| **ハルシネーション** | Hallucination | モデルが事実でない内容をもっともらしく生成する現象。エージェント構成では存在しないカラム名を出力してスキーマ違反を起こすなど実害に直結するため、RAGによる根拠付けや、外部コンパイラ・独立した判定アンサンブルでの検証と組み合わせて抑え込む。 |
| **RAG** | Retrieval-Augmented Generation（検索拡張生成） | 外部の文書を検索して取得し、その内容を根拠に回答を生成する構成。社内規程・契約書・業務マニュアルを直接参照させることでLLM特有のハルシネーションのリスクを大きく下げられるため、企業導入で最初に採られる定番の手法。 |
| **合成データ** | Synthetic Data | 実データではなくモデル自身が生成した学習データ。実データの枯渇やプライバシー制約を回避できる一方、生成物での再学習を重ねると品質が劣化するため、検証器による選別や実データとの混合を前提に使われる。 |
| **世界モデル / WFM** | World Foundation Model | 物理世界の振る舞いを学習した基盤モデル。NVIDIA Cosmos 3 などが該当し、Mixture-of-Transformers（MoT）を基礎にセンサー入力から物理的な因果を予測する。フィジカルAI・デジタルツインの中核。 |
| **Terminal-Bench / Terminal-Bench-Science** | （ベンチマーク名。正式な英語展開なし） | エージェントにターミナル環境での多段階の実行タスクを解かせ、完了率で性能を測るベンチマーク。Claude Fable 5.1のTerminal-Bench 4.0で55.8%、Mythos 5.1で60.9%のように主要モデルの発表記事で繰り返し引用される共通のものさしになっている。科学研究タスクに特化した派生版Terminal-Bench-Scienceでは、Fable 5の24.7%からFable 5.1で52.6%へ倍増した例がある。 |
| **Artificial Analysis Intelligence Index（AAスコア）** | Artificial Analysis Intelligence Index | 第三者評価機関Artificial Analysisが複数のベンチマークを統合して算出する総合的なモデル性能指標。Claude Fable 5.1が66点でOpus 5の63点を上回り、Gemini 3.8 FlashがGPT-5.6 Solと並ぶ59点、6000億パラメータのStep 5 Previewが44点でMoonshot AI「Kimi K3」と同水準、のようにモデル間比較の共通指標として使われる。 |
| **DeepSWE** | （展開形なし。SWEはSoftware Engineeringの略とみられる） | 長時間のソフトウェア開発タスクの遂行力を測るエージェント型ベンチマーク。DeepSeek V4 Proがプレビュー版から正式版で12.8点から62.7点へ急伸、Gemini 3.8 FlashがDeepSWE v1.1で73.7%を記録しClaude Opus 5の74.0%に迫るなど、コーディングエージェントの実力比較で繰り返し引用される。 |
| **Deep Think** | Google / DeepMind | Gemini 3.5 Proへの搭載が見込まれている、時間をかけてじっくり思考する推論モードの名称。200万トークンのコンテキストウィンドウとあわせて2026年7月のリーク報道で繰り返し言及されたが、Gemini 3.5 Pro自体の一般提供は9月時点でも延期が続いており、正式な仕様は確定していない。 |

## 3. フィジカルAI・ロボティクス

| 用語 | 正式名称 / 読み | 意味 |
|---|---|---|
| **フィジカルAI / エンボディドAI** | Physical AI / Embodied AI | AIを現実世界の物理システムに組み込み、センサーフュージョンによる環境知覚 → 自律的なリアルタイム判断 → 物理的な動作実行（アクチュエーション）までを一貫して行う形態。製造業向けヒューマノイド市場は2026年に74.3億ドル、2035年に2,713億ドル（CAGR 49.15%）と予測される。 |
| **VLA** | Vision-Language-Action | 視覚入力と言語指示から直接ロボットの行動を出力するモデル。最大の課題は遅延で、数秒考え込んでいる間に状況が変わってしまう。人間の二重過程理論を模したFiS-VLAのように、速い系と遅い系を分けるアーキテクチャで解かれつつある。 |
| **FiS-VLA** | Fast-in-Slow VLA | 人間の「二重過程理論（Dual Process Theory）」を模倣し、速い反射的制御ループの中に遅い熟考ループを埋め込むことで、推論時スケーリング最大の課題である遅延を解決したVLAアーキテクチャ。 |
| **Sim-to-Real** | Simulation to Reality（シミュレーションから現実へ） | 仮想空間（デジタルツイン）でロボットを大量に訓練し、学習済みモデルを現実の実機へ転送する手法。数百万回の試行錯誤を数時間で完了でき、実機のティーチング工数とライン停止時間を大幅に削減できる。仮想と現実の物理的なずれをどう埋めるかが成否を分ける。 |
| **デジタルツイン** | Digital Twin | 現実の設備・工場・都市を仮想空間に同期再現したもの。NVIDIA Isaac SimやOpenUSDを用いて仮想空間でロボットを訓練し、学習済みモデルを実機へ転送するSim-to-Realの前提となり、物理的なティーチングの手間とライン停止時間を削減する。 |
| **Omniverse / Isaac Sim** | NVIDIA | NVIDIAが提供する、物理的に正確なレンダリングと物理演算を備えたシミュレーション基盤。ロボットを仮想空間で訓練するSim-to-Realのワークフローの中核で、FANUCやSCSKなど日本の製造・SIerでも採用が進んでいる。OpenUSDを共通フォーマットとして使う。 |
| **Cosmos** | NVIDIA Cosmos | NVIDIAの世界基盤モデル（WFM）。物理世界の挙動を学習しており、ロボットや自動運転の訓練データを合成したり、行動の結果を予測したりする用途に使われる。COMPUTEX 2026で Cosmos 3 が発表され、フィジカルAIの基盤レイヤーという位置づけが強まった。 |
| **OpenUSD** | Open Universal Scene Description | 3Dシーン記述のオープン標準。もともとPixarが開発したもので、フォトリアリスティックな物理デジタルツインを構築する際の共通フォーマットとして採用されている。異なるCADやシミュレーターの間でシーンを持ち回れることが、産業用途での採用理由になっている。 |
| **ロボティクス・サプライチェーン問題** | Robotics Supply Chain Bottleneck | マッキンゼーが「人型ロボット量産の最大かつ最も過小評価されたボトルネック」と警告した部材調達の制約。減速機・アクチュエータ・高精度センサーなど、ソフトウェアと違って増産に物理的なリードタイムがかかる部品が律速になる。モデル性能が上がっても台数が伸びない要因。 |
| **データリアリズム / R2S2R** | Data Realism / Real-to-Sim-to-Real | 視覚的な写実性ではなく、質量・摩擦・弾性まで現実と物理整合したシミュレーションの精度を指す概念と、現実→シミュレーション→実機を循環させて学習を繰り返す訓練パイプライン。物理整合エンジンにより実機データ1単位に対し合成データ15単位相当の学習価値(1:15)を達成した例があり、ゼロショット展開での作業成功率90%、未知環境への汎化性能50%向上を実証している。Sim-to-Realをさらに反復的に回す発展形と位置づけられる。 |
| **ANSI/A3 R15.06-2025** | American National Standards Institute / Robotic Industries Association 規格 | 人間と同一空間で稼働する自律型ロボットに求められる産業安全規格。人間が一定距離内に侵入した際に200ミリ秒以内で完全停止・減速する監視機能や、転倒時に作業者を巻き込まない自律倒れ込み制御が要件となる。床面の傾斜・凹凸を3mm以内に抑えるサイトレディネスや500ルクス以上の照度確保と合わせ、ヒューマノイド現場配備の実務的なハードルとして扱われる。 |

## 4. 半導体・インフラ・電力

| 用語 | 正式名称 / 読み | 意味 |
|---|---|---|
| **HBM / HBM4** | High Bandwidth Memory | GPUのすぐ横に積層される広帯域メモリ。推論では演算能力よりメモリ帯域が先に頭打ちになるため、世代更新がそのまま性能に直結する。NVIDIA Vera Rubin は288GBのHBM4と22TB/sの帯域幅を備え、HBMの供給量自体がAIチップの出荷量を縛る構図になっている。 |
| **CoWoS** | Chip on Wafer on Substrate | TSMCの先進パッケージング技術。GPUダイとHBMを1つのパッケージに統合するもので、この工程の生産能力がAIチップ全体の供給制約になっている。TSMCの設備投資ガイダンス引き上げがニュースになるのも、多くがこの増強に向かうため。 |
| **NVL72 / ラックスケール** | NVIDIA NVLink 72 | GPU 72基をNVLinkで密結合し、1ラックを1つの巨大なアクセラレータとして扱うNVIDIAの構成単位。性能比較の粒度がチップ単体からラック単位へ移ったことを象徴し、AMDのHeliosなど競合も同じラック単位で性能とトークン単価を競う。 |
| **Blackwell / Vera Rubin** | NVIDIA | NVIDIAのGPUアーキテクチャの世代名。Blackwellの次がVera Rubinにあたる。Vera Rubinは前世代比で推論性能5倍、トークン単価10分の1を謳い、HBM4とNVL72のラックスケール構成を前提とする。世代交代の速さ自体がデータセンター投資の減価償却期間の議論を呼んでいる。 |
| **液冷（DTC / 液浸）** | Direct-to-Chip / Immersion Cooling | 空冷では処理できない高発熱GPUを冷やす方式。冷却液（プロピレングリコール水溶液等）の熱酸化で有機酸が発生しpHが低下、コールドプレートの微細流路を詰まらせるという化学的課題がある。 |
| **CDU** | Coolant Distribution Unit | 液冷ループの熱交換と冷却液の分配を担う装置。発熱1kWあたり1.25〜2.0 L/分の流量をインバーターポンプで可変制御し、100 psi（690 kPa）級の高圧に耐える設計が求められる。空冷から液冷への全面移行で需要が急拡大している部材。 |
| **OCP** | Open Compute Project | データセンター機材の標準化団体。ASHRAEとともに液冷（DTC・液浸）の技術パラメーターや部材仕様の標準化を進めており、リーク検知ロープセンサー、pH管理された二次冷却ループ、100 psi対応CDUなど、OCP準拠が新設・改修設計の前提条件になりつつある。 |
| **SMR** | Small Modular Reactor（小型モジュール炉） | データセンターのベースロード電源として契約が急増している小型原子炉。パイプライン契約量は2024年末の25GWから2026年に45GWへ倍増。 |
| **PPA** | Power Purchase Agreement（電力購入契約） | 電力を直接購入する長期契約。ハイパースケーラーが再エネや原子力を確保する主要手段で、MicrosoftはConstellation Energyと20年契約を結び、スリーマイル島1号機の再稼働で835 MWを確保した。SMRの商用化と同期した「SMR-Ready PPA」も視野に入る。 |
| **IOWN / APN** | Innovative Optical and Wireless Network / All-Photonics Network | NTTが推進する光ネットワーク構想と、その中核である端から端まで光のまま伝送する技術。光電変換の遅延と電力消費を削減し、東京〜福岡（約1,000km）等で実証済み。再エネ余剰地域へAI演算タスクを動的に移動させる運用が可能になる。 |
| **光電融合** | Photonics-Electronics Convergence / CPO（Co-Packaged Optics） | 電気信号処理と光信号処理を1チップ上で統合する技術。銅配線の消費電力と距離の限界を超えるための本命で、NTTのIOWN構想の基盤でもある。CPOの採用率は2026年の0.5%から2030年に35%へ拡大すると予測され、データセンター内配線の置き換えが始まっている。 |
| **GW / TWh** | ギガワット / テラワット時 | データセンターの電力規模を表す単位。GWは瞬間的な容量、TWhは年間の消費量を指す。AIインフラの議論では、確保できた電源の容量と、それが送電網に与える年間負荷が別々に問題になるため、両方が併記されることが多い。 |
| **CapEx** | Capital Expenditure（設備投資） | データセンターやGPUなどに投じる設備投資額。AI各社の本気度を測る中心指標で、TSMCが2026年のガイダンスを520〜560億ドルから600〜640億ドルへ引き上げた例のように、上方修正そのものがニュースになる。 |
| **Jalapeño** | OpenAI（Broadcomと共同開発） | OpenAIがBroadcomと共同開発した初の自社製推論専用チップ。SemiAnalysisの公開ベンチマークInferenceXでの測定では電力あたりの処理性能でNVIDIAのBlackwellおよびVera Rubinを上回ったと報告されたが、HBM4を使うJalapeñoと旧世代メモリのBlackwellとの比較は不公平との指摘もあり、まだエンジニアリングサンプル段階にとどまる。巨大チップベンダーへの一方的な依存を減らす動きの一例とされる。 |

## 5. ビジネス・市場

| 用語 | 正式名称 / 読み | 意味 |
|---|---|---|
| **CAGR** | Compound Annual Growth Rate（年平均成長率） | 複数年の成長を1年あたりの平均成長率に均した指標。市場規模の予測で最も多用され、本サイトでも「2025年の537億ドルから2035年に9,884億ドル、CAGR 31.6%」のように、始点と終点の金額とセットで提示される。 |
| **ARR / CAC** | Annual Recurring Revenue / Customer Acquisition Cost | 年間経常収益と顧客獲得コスト。AIスタートアップの評価で使われる基本指標で、ARRの伸びに対してCACが見合っているかが、シート課金から成果連動課金への移行の議論や、AIバブル論の土台になる。 |
| **ROI** | Return on Investment | AIエージェント本番運用の平均ROIは171%（米国企業は192%）。一方MITの調査ではパイロットの95%が定量的成果なく終了しており、実装の巧拙で二極化している。 |
| **PoC** | Proof of Concept（概念実証） | 本格導入の前に有効性を検証する小規模な試行。本サイトでは「PoCの時代は終わった」という否定的な文脈で頻出し、生成AIのPoCの95%が損益計算書上の実質的なインパクトを生めていないという調査が繰り返し引用される。 |
| **シート課金 → 成果連動課金** | Per-seat → Outcome-based Pricing | SaaSの標準だったユーザー数課金から、成果に応じた課金への移行。エージェントが人間の作業そのものを代替するとユーザー数が増えないどころか減るため、ユーザー数課金では価値と収益が連動しなくなる。既存契約の改定交渉が業界全体で進んでいる。 |
| **FinOps** | Financial Operations（クラウド財務管理） | クラウドやAI推論のコストを可視化し、継続的に最適化する運用規律。高額なフロンティアモデルへの過度な依存から脱し、定型タスクをオープンウェイトモデルや特化型の小型モデルへ動的に振り分ける階層型アーキテクチャと組で制度化することが求められる。 |
| **垂直統合 / バーティカルAI** | Vertical AI | 汎用モデルではなく、特定業界の現場データとワークフローに密着させたAI。データもワークフローも外部から模倣しにくいため、汎用モデルの性能向上に飲み込まれにくい参入障壁になる。医療のSaMDや製造の現場データ活用がその典型例として挙げられる。 |
| **GEO** | Generative Engine Optimization（生成エンジン最適化） | AI検索の回答内に自社コンテンツを引用させるための最適化施策。従来のSEOが検索結果の順位を争ったのに対し、GEOは要約された回答の中に引用として残ることを狙う。NTTの事例では引用率が70%まで向上したと報告されている。 |
| **AEO** | Answer Engine Optimization（回答エンジン最適化） | AIが「唯一の正解」として自社を選ぶことを狙う最適化。AI生成サマリーが表示されるとCTRは平均15.5%低下するため、従来SEOのクリック率指標が意味をなさなくなったことへの対応。 |
| **AIバブル / 循環取引・ベンダーファイナンス** | Circular Deals / Vendor Financing | チップメーカーがAI企業に出資し、その資金で自社チップが買われるという資金の循環構造への懸念。売上が実需ではなく自社の出資で作られているのではないかという指摘で、CapExの伸びやARR成長の実態を評価する際に必ず持ち出される論点になっている。 |
| **主権AI / ソブリンAI** | Sovereign AI | 自国のデータやAIモデルの学習・運用基盤を外国企業の管理下に置かず、自国内で完結させようとする政策・事業の方向性。インドのHCLTechが「オディシャ・ソブリンAIパーク」でデータセンターを新設した例や、EUが公的資金100億ユーロで最大7拠点の「AIギガファクトリー」公募を始めた例、マレーシアが米国の警告を押し切りHuawei製チップの採用を検討する例など、米中いずれの陣営にも一方的に依存しない独自路線の文脈で繰り返し使われる。 |
| **FDE** | Forward-Deployed Engineer（フォワード・デプロイド・エンジニア） | 顧客企業のオフィスに常駐し、AIエージェントの実装まで担うエンジニア職種の呼び名。OpenAIの事業展開部門がNorthslopeを買収してこの人員を数百人規模に拡大したほか、AmazonもAWS内に同様の常駐組織へ10億ドルを投じるなど、AIを売り切りのソフトウェアではなく導入まで伴走するサービスとして提供する事業モデルの中核を担う。 |
| **RVG（残価保証）** | Residual Value Guarantee | 半導体大手が顧客企業の設備投資を後押しするため、機器の将来の中古価値を一定水準まで保証する金融手法。NVIDIAやBroadcomなどのRVG総額は約700億ドルに達したとされ、米国の会計ルールでは損失発生が確実視されるまで負債計上義務がなくバランスシートに載らないまま膨張している。AIバブル論や循環取引・ベンダーファイナンスの議論とあわせて語られる仕組み。 |

## 6. 安全性・ガバナンス・規制

| 用語 | 正式名称 / 読み | 意味 |
|---|---|---|
| **AGI** | Artificial General Intelligence（汎用人工知能） | 人間並みに幅広いタスクをこなせる知能。到達の定義が曖昧なため、本サイトでは経済的な成果で線を引くECIや、自己改良が止まる条件を扱う「AGI力学」のように、より測定可能な議論へ置き換えて語られる場面が多い。 |
| **ECI** | Economically-Comparable Intelligence（経済的に同等な知能） | AGIより実務的な到達基準として使われる概念。人間の経済活動と同等の価値を生む知能を指す。「万能な知能」という曖昧な定義を避け、経済的な成果で線を引く点に特徴があり、到達時期の議論でAGIの代わりに用いられることが増えている。 |
| **RSP** | Responsible Scaling Policy（責任あるスケーリング政策） | フロンティアラボが自主的に課す安全枠組み。危険なケイパビリティ（CBRN、自律的ハッキング、自己複製）を検知した際の対応を規定する。RSP v3.0では法的拘束力を持つ一時停止条項が、努力目標の「Frontier Safety Roadmaps」へ置き換えられた。 |
| **Preparedness Framework** | OpenAI | OpenAIの安全評価枠組み。最高危険水準は「Critical」で、次世代モデル「Astra」がサイバー分野でこれに到達する可能性から開発の一部が停止された。 |
| **ASF 2.0** | AI Safety Framework | NAVERが2026年7月の人工知能安全ソウルフォーラムで公開した枠組み。評価の焦点をモデル性能から「コンテキスト」「ユースケース」「インパクト」の3軸に細分化した。 |
| **ISO/IEC 42001（AIMS）** | AI Management System | 組織全体のAI運営方針・責任の所在・データガバナンスを定める国際規格。認証取得が調達条件になる例も出ており、EU AI Actへの適合を示す実務的な手段としても使われる。IETF AIMS（エージェント認証標準）とは同名の別物なので、文脈で読み分ける必要がある。 |
| **NIST AI RMF** | AI Risk Management Framework | GOVERN / MAP / MEASURE / MANAGE の4機能を回す実務プロセス。ISO 42001が「組織の枠」、RMFが「中身の実装」という役割分担で統合運用される。 |
| **EU AI Act** | EU人工知能法 | リスクに応じてAIシステムを分類し義務を課すEUの包括規制。第50条の透明性義務（AI生成物への電子透かし等）は2026年8月2日から適用されている。2026年6月にはAI Act簡素化パッケージがEU理事会で最終承認され、高リスクAI義務の適用延期が盛り込まれた。 |
| **NFR** | Non-Functional Requirements（非機能要求） | 倫理指針を「理念表明」ではなく契約上の義務として調達仕様に落とし込む考え方。ISO 42001 / NIST AI RMF / EU AI Act を契約レベルで実装する。 |
| **AIBOM** | AI Bill of Materials | ソフトウェアのSBOMに相当する、AIシステムの構成部品表。SPDX 3.0 / CycloneDX 1.7 が採用規格で、先進的な調達では提出が前提条件化しつつある。 |
| **アライメント** | Alignment | モデルの振る舞いを人間の意図・価値観に一致させること。人間選好に基づくRLHFが代表的な手法だが、人間の評価能力の限界・一貫性の欠如・評価コストがボトルネックとなり、大規模な自律学習ループを閉じる妨げになると指摘されている。 |
| **ガードレール** | Guardrails | モデルやエージェントの出力・行動を制約する安全機構。ハーネスの構成要素の一つであると同時に、自律型ビジネスの文脈では「意思決定の境界線」そのものを指し、ガーディアンエージェントによるリアルタイム監査とセットで設計される。 |
| **レッドチーム** | Red Teaming | 攻撃者の視点で意図的にモデルの脆弱性を探す評価手法。AIエージェントの実運用拡大に伴って専業化が進み、Anacondaによる Enkrypt AI 買収のように、レッドチーム評価とガードレールを持つ企業がセキュリティ基盤へ取り込まれる動きが出ている。 |
| **CBRN** | Chemical, Biological, Radiological, Nuclear（化学・生物・放射性物質・核） | フロンティアモデルの危険ケイパビリティ評価で中心となるリスク領域。AnthropicのRSP、OpenAIのPreparedness Framework、EUのGPAI行動規範のいずれもCBRNを主要ハザードに挙げ、閾値を超えた場合の開発停止や追加セーフガードを義務づけている。 |
| **タスク指向型無謀さ** | Task-Oriented Recklessness | 悪意ではなく「与えられた目的を何としても達成しようとする」ことから生じる危険行動特性。マルチエージェント型自己改良システムで最も深刻な問題として特定された。 |
| **来歴 / 電子透かし** | Provenance / Watermarking | AI生成コンテンツの出所を追跡可能にする仕組み。EU AI Act第50条の透明性義務では、AIとの対話であることの明示と、生成・改変コンテンツへの機械可読な電子透かしの付与が求められ、2026年8月2日から適用が始まっている。 |
| **MAISI** | Mathematical AI Safety Institute | 2026年フィールズ賞受賞の数学者ジェイコブ・ツィマーマン氏が2026年9月に設立を発表した、AI安全性の理論基盤を数学的に整備する研究機関。 |
| **WAICO（世界AI協力機構）** | World AI Cooperation Organization | 中国の習近平国家主席が2026年7月にWAIC(世界人工知能大会)で自ら提唱し、ロシア・パキスタン・ラオスなど29か国が創設に参加した、上海に本部を置く中国主導の国際AIガバナンス機構。米欧日主導の枠組みと並立する形で国際的なAIルール形成の二極化を象徴し、米政権は自陣営「パックス・シリカ」の参加国に重複加盟を控えるよう警告している。 |
| **パックス・シリカ** | Pax Silica（本文中に英語表記なし） | 米国が主導する、AI半導体・インフラの供給網を同盟国で固める枠組みの通称。2025年末に発足し日本・韓国・豪州・EU加盟国など二十数か国・地域が参加している。トランプ政権は2026年8月、参加30か国以上に対し中国主導の世界AI協力機構（WAICO）へ重複参加しないよう警告する書簡を送り、両陣営の分断を鮮明にした。 |
| **SB 53** | California Senate Bill 53（カリフォルニア州上院法案53号） | カリフォルニア州が制定したフロンティアAIの安全性に関する州法の通称。OpenAIはかつてこの法案に反対していたが、2026年8月22日にはフロンティアAI安全の「重要な土台」と評価したうえで、逆にさらなる強化を自ら求める声明を出した。連邦レベルの統一立法が進まない中、州レベルの規制が先行するAIガバナンスの構図を象徴する法律として扱われる。 |
| **ZDR（ゼロデータ保持）** | Zero Data Retention | 顧客がAIサービスに送信したデータをモデル提供企業側が一切保持しない契約形態。機密情報を扱う企業がAIを導入する際の標準的な条件の一つとして使われ、OpenAIは2026年8月20日、ZDR契約の顧客に対しても不正利用の兆候を検知できる新方式「Private Safety Processing」を発表し、プライバシー保護とセキュリティ監視の両立を試みている。 |
| **DSA / VLOSE** | Digital Services Act（デジタルサービス法）/ Very Large Online Search Engine（超大規模オンライン検索エンジン） | EUの巨大デジタルプラットフォーム規制法であるデジタルサービス法（DSA）と、その中でEU域内月間利用者4500万人超のサービスに課される最重区分VLOSE。ChatGPTは2026年8月末にVLOSEへ指定され、公開広告アーカイブの整備や研究者へのデータ提供などが年内に義務化される。同法が定める研究者向けAPIは、GoogleのAI Overviewsの偏りを検証した調査でも根拠として使われている。 |
| **EU KIDS Act** | （英語正式名称は本文未記載。子どものオンライン安全に関するEU新法案） | 欧州委員会が2026年9月17日に公表した、子どものオンライン安全を強化する新法案。AIチャットボットやコンパニオンAIを18歳未満に対して既定でオフにすることや、無限スクロールなど依存を助長する設計手法の制限を義務づけ、大規模プラットフォーム事業者に自社サービスの安全性を自ら証明する責任を課す。既存のEU AI Actとは別建ての児童保護特化の規制枠組み。 |

## 7. セキュリティ

| 用語 | 正式名称 / 読み | 意味 |
|---|---|---|
| **ゼロデイ / エクスプロイト** | Zero-day / Exploit | 未知の脆弱性と、それを突く攻撃コード。Claude Mythos Preview が主要OS・ブラウザの未知脆弱性を自律的に発見し動作するエクスプロイトを設計できたことが、一般公開凍結の理由になった。 |
| **DIS** | Digital Immune System（デジタル免疫システム） | Gartnerが提唱した、生体免疫系に着想を得たインフラ保護概念。設計・開発・自動化運用・高度アナリティクスを統合し、障害や攻撃に対して自律的に防御と自己修復を行う。シグネチャ依存型・境界防御型の限界への対応。 |
| **MPA** | Multi-Party Approval（複数当事者承認） | システム全消去などの破壊的な操作に、あらかじめ指定された2人以上の承認を必須にする機能。最上位の管理者権限が乗っ取られた場合でも、人間の承認か独立したセキュリティポリシーの照合が得られない限り実行されない点が要点。 |
| **SPIFFE / SPIRE / WIMSE** | Workload Identity in Multi-System Environments | ワークロードに動的にIDを発行・検証する仕組み。静的なAPIキーやbearerトークンの運用を「反パターン」として置き換える、エージェント認証の基盤。 |
| **Daybreak** | OpenAI | 防御側に脆弱性発見能力を提供するプログラム。通常版の「Daybreak Blue」と、ゼロデイ発見・攻撃チェーン検証まで踏み込める「GPT-5.6-Cyber」を使える「Daybreak Red」の2階層構成。 |

## 更新方針

このファイルが用語集の原本。`scripts/generate_glossary_data.py` が `history/glossary-data.js` を生成し、`history/glossary.html` がそれを読む。**生成物とHTMLは直接編集せず、必ずここを編集して再生成する。** 週次のレポート更新（`sync-news-html` スキル）と日次のニュース更新の最後に、この手順が実行される。

- 新しい用語がニュースに登場したら、該当カテゴリの表に1行追加する。新しい章は作らない
- サイト内に実際に登場する用語だけを収録する。一般的なAI辞書に寄せない
- 定義は「サイト内でどう使われているか」を優先し、一般的な辞書定義に寄せすぎない
- **正式名称 / 読み列は必ず埋める。** 展開形が本当に存在しない語だけ空欄にしてよい
- **意味 / 補足列は必ず3行以上（全角70文字以上）書く。** レポート本文の固有名詞・数値・事例を1つ以上含める
- **意味 / 補足列に太字（`**`）を使わない。** カード内で浮くため
- モデル名・シリーズ（9章）は更新頻度が高いため、主要なものに絞って維持する。区切りは半角スラッシュ `" / "` に統一し、スマホ幅390pxでカード見出しが1行に収まる長さに保つ。モデルではない製品名をモデル一覧に混ぜない
- 編集後は `python3 scripts/generate_glossary_data.py` を実行する
