# Scaling up Test-Time Compute with Latent Reasoning：初学者向け解説

## 1. この論文は何を解決しようとしたのか

この論文は、言語モデルの回答性能を、モデルを大きくしたり学習データを増やしたりせず、回答を出す直前の計算量を増やすことで改善する研究です。特に、推論の途中を自然言語の長い文章として出力せず、内部の連続値ベクトルを繰り返し計算します。

通常のChain-of-Thought（CoT）は、「まず条件を整理し、次に計算する」のような中間文章を生成します。文章として考えるため人間が読みやすい一方、考えるたびにトークンを生成し、メモリも使います。この論文は、言語化する前の内部計算を増やす「latent reasoning」に注目します。

## 2. 読む前に知っておきたい用語

| 用語 | 意味 |
|---|---|
| 推論時計算（test-time compute） | 学習後、質問に答えるときに使う計算量 |
| 潜在表現 | モデル内部の、数値ベクトルによる情報表現 |
| recurrent depth | 同じ計算ブロックを深さ方向に繰り返して実効的な深さを増やす構造 |
| Prelude / Core / Coda | 入力を整える部分、反復計算部分、出力へ戻す部分 |
| 反復回数 `r` | Coreを何回繰り返すか |
| KV-cache | Attentionで過去のKeyとValueを保存し、再計算を省く仕組み |
| 早期終了 | 十分に状態が安定したトークンの計算を途中で止めること |
| 自己投機的デコーディング | 少ない反復で候補を作り、多い反復で同じモデルが確認する方法 |

## 3. モデルの構造

モデルは、入力トークン列をまずPreludeに通して、問題文の内部表現 `e` を作ります。その後、Coreという同じTransformerブロックを繰り返し実行します。

```text
入力文 x → Prelude P → e
                    ↓
       s0 → Core R → s1 → Core R → s2 → ... → sr
                                                        ↓
                                             Coda C → 次トークンの確率
```

式で書くと、次のようになります。

```text
e = P(x)
s_i = R(e, s_{i-1})
p = C(s_r)
```

Core `R` は毎回同じ重みを使います。したがって、パラメータ数を増やさずに同じ計算を何度も重ねられます。最終モデルは実際の層が8層ですが、反復回数32では、Core 4層を32回使うため、実効的には132層相当の計算になります。

これは「大きなモデルを一度だけ使う」のではなく、「同じ小さめの思考部品を何度も使う」設計です。簡単な問題には少ない反復、難しい問題には多い反復を使える可能性があります。

## 4. 学習と推論の流れ

### 学習時

推論時に反復回数を増やしたときにも性能が上がるよう、学習中から反復回数を毎回変えます。通常は少ない回数を選び、ときどき非常に長い計算も行う分布を使います。

すべての反復を保存して逆伝播するとメモリを大量に使うため、最終モデルでは最後の8反復を中心に勾配を戻す、深さ方向のTruncated Backpropagationに近い工夫を使います。また、内部状態がどの反復でも同じになる表現崩壊や、Coreが入力を無視する問題を、正規化やadapterなどで抑えます。

### 推論時

学習済みモデルに質問を与え、反復回数 `r=4, 8, 16, 32` などを指定して答えを生成します。文章の中のすべてのトークンに同じ回数を割り当てることもできますが、隣り合う反復の出力分布がほとんど変わらなくなったトークンだけ先に止める適応的計算も試せます。

## 5. 実験結果の読み方

反復回数を増やすと、いくつかのベンチマークで性能が上がりました。

| タスク | r=4 | r=8 | r=16 | r=32 |
|---|---:|---:|---:|---:|
| ARC-Easy | 49.07 | 65.11 | 69.49 | 69.91 |
| ARC-Challenge | 27.99 | 35.15 | 37.71 | 38.23 |
| HellaSwag | 43.46 | 58.54 | 64.67 | 65.21 |
| OpenBookQA | 28.20 | 35.40 | 37.60 | 38.80 |

反復を増やせば無限に性能が上がるわけではありません。HellaSwagのように早く飽和するタスクもあれば、ARC-Challengeや数学のように長い計算を利用しやすいタスクもあります。

同じ学習条件の固定深度モデルとの比較では、r=32の再帰モデルがHellaSwag、PiQA、SciQ、GSM8K CoTなどで上回りました。r=1では性能が大きく下がるため、効果の中心はPreludeやCodaではなく、Coreを繰り返すことだと考えられます。

## 6. 実用上の工夫と意味

- **トークンごとの適応的計算**：簡単な部分は早く止め、難しい部分だけ長く考える。
- **KV-cache共有**：各反復の記憶を一定のスロットで共有し、長い生成のメモリを抑える。
- **Continuous CoT**：直前のトークンで得た内部状態を次のトークンの初期状態として再利用する。
- **自己投機的デコーディング**：少ない反復で候補を作り、多い反復で同じモデルが検証する。

これらは、推論能力だけでなく、計算コストやメモリ使用量も考慮して潜在推論を使うための工夫です。

## 7. Coconutとの違い

Coconutも、自然言語の代わりに内部ベクトルで考える研究です。ただし、CoconutはCoTの言語ステップを潜在思考へ段階的に置き換え、複数の候補を探索できるかを主に調べています。一方、この論文は同じCoreを深さ方向に繰り返し、推論時の計算量を反復回数でスケールさせる設計と、早期終了・KV-cache共有などの実用性に重点があります。両者は関連しますが、同じ手法ではありません。

## 8. 限界と今後の課題

- 主な大規模実験は3.5Bモデルを1回学習した結果で、より大きなモデルへの一般化は未確認です。
- 800Bトークンの学習や多数回の推論には大きな計算資源が必要です。
- 潜在状態は人間が読める思考文ではないため、誤りの原因や安全性を監査しにくい。
- 内部状態の軌道が観察されたからといって、それが人間と同じ意味での「思考」と証明されたわけではありません。

次に学ぶなら、Transformerの深さとパラメータ数の違い、RNNの重み共有、推論時スケーリング、CoTと潜在推論の安全性を調べると理解が深まります。

## 9. まとめ

この論文は、同じTransformerブロックを内部表現に何度も適用することで、モデルのパラメータ数を増やさず、回答前の計算時間を増やして推論性能を高める方法を示しました。
