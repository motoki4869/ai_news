# 論文の要約＆かんたん解説

## Overview

`ai_news/article/<論文タイトル>/` 配下のPDF論文を指定されたら、その**同じフォルダ**に日本語で2つのファイルを作る：①専門的でしっかりした要約、②小学生でも理解できるかんたん解説。ユーザーが「要約して」としか言わなくても、**必ず両方**作る。これがこのスキルの主目的であり、「要約だけ」で止めるのは仕様漏れである。

## When to Use

- ユーザーが論文PDFのファイル名・タイトル・「この論文」等で対象を指定し、要約・解説・「わかりやすくして」を依頼したとき
- 対象PDFが `ai_news/article/` 配下のどこにあるか不明なときは、`find` 等でタイトルの一部から検索する。複数候補や見つからない場合はユーザーに確認する
- 依頼が「要約だけでいい」「かんたん解説はいらない」と明示されている場合のみ、要約ファイルのみを作る（この除外が無ければ常に両方作る）

要約・かんたん解説を作った後は、必ず`③関連ドキュメントの更新`まで実施する。

## ファイル出力ルール

- 保存先: PDFと**同じフォルダ**
- ファイル名: PDFのベース名（拡張子なし、フォルダ名と同じタイトル表記をそのまま使う）に接尾辞を付ける
  - `<論文タイトル>_要約.md`
  - `<論文タイトル>_かんたん解説.md`
- 出力は全て日本語（コード・数式・固有名詞は英語のままでよい）

## PDFの読み方

- Readツールは1回20ページまで。ページ数が多い論文は `pages: "1-12"`, `"13-25"` のように分割して読む
- 本文（Abstract〜Conclusion）と主要な実験結果の図表・数式は必ず読む。参考文献リストは流し読みでよい。付録は、要約に必要な実験詳細があれば読み、大量のサンプル画像やチェックポイント一覧などボリュームだけで内容が薄い部分は読まなくてよい

## ①要約ファイルの構成

論文ごとに見出しは調整してよいが、以下の深さ・網羅性を目安にする（浅い箇条書き数行では不十分）：

1. タイトル・著者・発表年・出典（学会/arXiv番号）
2. 概要（2〜4文で何をした論文か）
3. 背景・動機（何が課題で、なぜこの研究が必要だったか）
4. 手法（モデルの仕組みを、数式や図の意味も含めて丁寧に説明する。既存論文の用語を借りるだけでなく、何をどう計算しているかを説明する）
5. 実験結果（主要な数値・比較表を含める）
6. 結論・今後の展望
7. 「この論文の意義（補足）」— 現在の生成AI（ChatGPT, Stable Diffusion等）にどうつながっているかを一言添える

## ②かんたん解説ファイルの構成

**専門用語を平易な言葉に置き換えるだけでは不十分。** 小学生が実生活で知っているもの（テレビの砂嵐、粘土をこねる、本を1ページずつしか読めない人、伝言ゲーム等）に例えて、論文の核心アイデアを体感させる。

1. 導入：この論文が何に使われているAIの話か（例："絵を描くAI"、"会話AI"の話）
2. 「この論文が思いついたアイデア」を身近な例えで説明（数式・専門用語は出さない）
3. 「なぜこれがすごいのか」を2〜3個のポイントに分けて説明
4. 今の生活で見るAI（ChatGPT・Stable Diffusion等）とのつながり
5. 「まとめ（1行で）」で1文に凝縮

## ③関連ドキュメントの更新

`ai_news/article/今のAI時代を作った偉大な人物.md` は、生成AIを作った人物とその代表論文を一覧化したドキュメントで、各論文が「要約済み」か「未要約」かをこのファイル自身が管理している。**要約・かんたん解説を作成したら、必ずこのファイルを開き、今回要約した論文に該当する記述があるか確認する。**

該当箇所があれば、以下の両方を更新する（ファイル内に該当箇所が無い場合は何もしなくてよい）：

1. 本文中の代表論文の行：`（未要約）`を、要約ファイルへのリンクに置き換える
   - 例：`（未要約）` → `[要約済み](<./<論文タイトル>/<論文タイトル>_要約.md>)`
   - 他の要約済み論文の記法（`[Attention Is All You Need（2017）](<./Attention Is All You Need/...>)`等）に揃える
2. 末尾の「まとめ表」の該当行：`未要約`のセルを`[要約済み](<...>)`のリンクに置き換える

このファイルが存在しない、または対象論文の言及が見当たらない場合は、更新をスキップしてよい（このスキルはドキュメントの新規作成までは行わない）。

## Quick Reference

| やること | 詳細 |
|---|---|
| 対象PDFを探す | `find <article配下> -iname "*キーワード*"` |
| PDFを読む | ページ分割（1回20ページ以内） |
| 要約を書く | `<タイトル>_要約.md`、専門的・網羅的 |
| かんたん解説を書く | `<タイトル>_かんたん解説.md`、身近な例え中心 |
| 両方作ったか確認 | 「要約だけ」の明示的除外が無い限り2ファイル必須 |
| 人物ドキュメントを更新 | `今のAI時代を作った偉大な人物.md`内の該当箇所（本文＋まとめ表）の「未要約」をリンクに置き換え |

## Common Mistakes

- **「要約して」だけの依頼でも、かんたん解説を省略してしまう** → このスキルが起動した時点で、明示的な除外がない限り両方作る
- ページ数の多いPDFを1回のReadで読もうとしてエラーになる → 分割して読む
- かんたん解説で専門用語を単に平易な言い換えに留める（例:「ノイズを除去する処理」→「きれいにする処理」）→ 具体的な身近な物事への例え（砂嵐、粘土等）に落とし込む
- 出力ファイル名がPDFのタイトル表記（大文字小文字・スペース）とズレる → フォルダ名/PDFファイル名の表記をそのまま踏襲する
- **要約・かんたん解説を作って終わりにし、`今のAI時代を作った偉大な人物.md`の「未要約」表記を放置してしまう** → 該当箇所があれば必ず本文とまとめ表の両方を更新する
